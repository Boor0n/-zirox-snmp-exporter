Подключение к Prometheus

Prometheus сам узнаёт список устройств и интервал каждого через HTTP Service Discovery. После добавления устройства в веб-интерфейсе ничего в Prometheus менять не нужно. Prometheus никогда не обращается к устройствам: он читает последние значения из памяти экспортера.

prometheus.yml

scrape_configs:
  - job_name: zirox-snmp
    http_sd_configs:
      - url: {{.Base}}/sd
        refresh_interval: 60s

Если задан ZIROX_SCRAPE_TOKEN, добавьте authorization: {credentials: "<token>"} и в http_sd_configs, и в саму задачу.

Каждое устройство становится отдельной целью с метками instance, device, group, address, sysName. Интервал сбора (__scrape_interval__) равен интервалу опроса устройства.

Альтернатива: одна цель со всеми устройствами

  - job_name: zirox-snmp-all
    scrape_interval: 60s
    metrics_path: /metrics/all
    static_configs:
      - targets: ['{{.Host}}']

Эндпоинты

/sdсписок целей для HTTP SD (JSON)
/probe?target=<id|имя|IP>метрики одного устройства
/metrics/allвсе устройства одним ответом, с метками device и group
/metricsсостояние самого экспортера

Примеры запросов для Grafana

rate(ifHCInOctets{device="core-nx-01"}[5m]) * 8          # входящий трафик, бит/с
rate(ifInErrors[5m]) > 0                                   # порты с ошибками
zirox_cpu_utilization_percent{window="1m"}                 # загрузка CPU
zirox_temperature_celsius                                  # температура
zirox_poll_success == 0                                    # устройства, которые не отвечают
