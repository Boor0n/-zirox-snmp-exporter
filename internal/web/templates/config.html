Backup and configuration

Full backup

The database and the encryption key in one .tar.gz: devices, ticks, credentials, users, change log. Restore it to move Zirox to another server or roll back; the archive has a RESTORE.txt with the commands.

{{if .KeyInEnv}}

The encryption key comes from ZIROX_SECRET_KEY, so it is not in the archive. Keep that value with the backup.

{{else}}

The archive contains the key that decrypts the stored communities and passwords: keep it as safe as the passwords.

{{end}} Download backup

Zirox also keeps the last 5 automatic copies of the database in data/backups/, written before each upgrade and import.

Configuration file

Settings, credentials, poll profiles, port rules, custom OIDs and devices with their ticked ports and roles, as YAML. Readable, fits in git, and can be imported on another server. Metrics and the change log are not included.

Export without secrets Export with secrets

Import a configuration

Devices are matched by name (or address), everything else by name; port rules in the file replace the current ones. Ticks and roles are restored on devices Zirox already knows; new devices get them after their first discovery. Credentials in the file without a secret are created empty, or left alone when they exist. Preview shows what would change; nothing is saved until you press Import. The database is backed up first.
